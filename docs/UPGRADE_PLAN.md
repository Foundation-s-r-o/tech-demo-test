# Upgrade State and Deferred Work

**Status:** current reference
**Purpose:** document the current platform baseline and the remaining deferred work.
This file is not a change log. Git is the history.

## Current Baseline

The upgrade target has been reached. The repository is now a small, Docker-free
reference template with this baseline:

| Area | Current state |
| --- | --- |
| Java | 21 LTS, pinned by `api/.sdkmanrc` |
| Spring Boot | 4.0.6 |
| Database | embedded H2 file-mode for local development and H2 in-memory for tests |
| Migrations | Flyway, portable SQL intent |
| Authentication | Spring Security session login with CSRF and exact-origin CORS |
| Demo users | seeded only by explicit local/test profiles |
| PDF | OpenPDF-backed person extract |
| Observability | Actuator + Micrometer only |
| Frontend | React 19, TypeScript 6, generated OpenAPI client |
| Verification | `./doctor` is the full local health check |

The current baseline deliberately excludes Redis, Redisson, Sleuth, OpenAI
Assistants, MariaDB, Testcontainers for the normal test path, Docker runtime
assets, and a production deployment definition.

## Current Quality Position

Use the running configuration and generated artifacts as the authority:

- `./doctor` runs the full local gate.
- `docs/trivy-report.txt` is the current Trivy table output.
- `docs/sonar-metrics-*.json` contains current Sonar metrics.
- `docs/sonar-issues-*.json` is intentionally compact and contains only active
  critical/high-priority Sonar issues.
- `SECURITY.md` owns security controls, caveats, and implementation gaps.
- ADRs own architecture decisions.

Do not keep separate historical quality summaries in this file.

## Deferred Work

These items are intentionally not part of the current demo baseline. Implement
them only when the repo is being prepared for a real deployment or when the
corresponding task in `TASKS.md` is selected.

| Priority | Work | Goal |
| --- | --- | --- |
| 1 | PostgreSQL production profile | Add a real production database path while preserving the fast H2 local loop. |
| 2 | MFA / stronger identity | Add production-grade account protection before exposing login beyond local/demo use. |
| 3 | Login throttling | Limit account and source-address brute-force attempts. |
| 4 | Secret management | Move production secrets to a vault, cloud KMS, or another deployment-owned secret manager. |
| 5 | TLS and deployment packaging | Define the runtime platform, TLS termination, and packaging after a threat model exists. |
| 6 | Full observability stack | Add OTel/Prometheus/Loki/Grafana only when it becomes supported runtime, not as local default weight. |
| 7 | Coverage ratchet | Raise the backend coverage floor toward the Sonar target as the business surface grows. |
| 8 | Dependency cleanup | Remove vestigial packages such as `@types/react-bootstrap` when lint/build verification confirms they are unused. |

## Constraints

- Keep local development Docker-free unless the selected task explicitly changes
  the runtime model.
- Keep migrations portable for the future PostgreSQL path.
- Keep authentication swappable: session login is the current implementation;
  future MFA or OIDC work must not leak provider assumptions into feature code.
- Keep observability lightweight until a real deployment target exists.
- Keep quality data generated by tools, not manually summarized in long-lived
  docs.

## Verification

Before treating a deferred item as complete, run the verification scope required
by `CLAUDE.md`. For cross-cutting changes, use:

```bash
./doctor
```

For documentation-only edits, use at least:

```bash
git diff --check
```
